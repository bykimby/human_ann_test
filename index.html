The situation behind every question

Someone is using the electronic product right now and a question comes up. They look at the device — a button, an icon, a light, a part — and ask about it. Write every question the way that person would ask it.

  • Describe the target as it appears on the product: its shape, colour, icon, and where it sits on the device.
  • Never point to a place on the manual page. The person asking has not seen the manual — finding that page is the system's job.
✓ Allowed“On the Hyundai Sonata 2026, what does the round button just left of the centre screen do?”
✗ Not allowed“What is the part in the figure at the top-left of the manual?” · “…in the bottom-right picture?”

Task

  • Query: Textual user query
  • Database: Manual PDF page images from multiple brands and products
  • Goal: Retrieve the relevant manual page and answer the query using both visual and textual information

Dataset Characteristics

  • The question must include the product's brand name and model name so that the correct manual can be retrieved from the full database.
  • Other than the brand and model name, the question must refer only to visual information, such as:
    • appearance or shape
    • color
    • icon appearance
    • button or component position
    • spatial relationship to surrounding elements
  • The question must not mention text shown on the target page, including:
    • component or button names
    • labels
    • menu names
    • function names
    • other textual descriptions that could directly identify the target
  • The question should therefore require the following process:
    brand & model → find the relevant manual → visual description → find the relevant page → identify the target visually → read the associated text → answer
  • Most manual pages are provided with a reference example containing:
    • Question
    • Answer
    • Text evidence
    • Image evidence
    • Bounding box for the image evidence
  • Annotators may use these examples as references when creating their own annotations.
  • Extra pages. Manuals alone may not offer enough suitable pages, so extra pages are included. An extra page has no reference example — only the page image and, where available, its ambiguous spans. Write the QA from the page itself, following the same rules.

Annotation Procedure

  • Each annotator is given 100 manual page images and their corresponding reference examples.
  • Review the 100 pages and select the pages most suitable for this task.
  • For each selected page, create one or two QA examples — at most two per page. A second QA on the same page must target a different visual element, with its own answer, evidence and bounding box.
  • For each example, annotate:
    • Question
    • Answer
    • Text evidence
    • Image evidence
    • Bounding box around the image evidence
  • The bounding box should cover only the specific visual element referred to in the question, not the entire figure or page.

⚠ Caution — pages that already have someone else’s QA

  • If another annotator has already written a QA on a page, you can see it but you cannot edit it.
  • Do not create the same data again. Your QA must not repeat their question, and must be about a different visual element — their bounding box is shown dashed on the page.
  • If you think their QA is wrong, do not write a corrected copy of it. Ask the coordinator to fix it, giving the page file name and the QA number.

Final Output

100 candidate pages → select the suitable pages → create up to 2 annotations per page → 50 or 100 QA examples per annotator — you choose one when you sign in.

Using this tool

How the software works. This is not part of the annotation specification above.

  • Open Annotate, sign in with your name in English, your email and your goal (50 or 100 QA; change it any time with Switch), and load the image ZIP you downloaded from the Drive link. The images stay in your browser and are never uploaded.
  • Pick a page from the list on the left. Press Not suitable on a page you are not selecting — it leaves your list and stays open to other annotators.
  • A QA becomes yours as soon as you start typing, and no one else can change it after that.
  • A page can carry up to two QA, and they do not have to be by the same person. Once you have written QA 1, + Add QA 2 appears — press it to write a second question about a different element on the same page. When someone else has finished QA 1 on a page, that page shows a half-filled dot in the list: open it and you land on QA 2, where you can add your own. You can read their QA 1, and its box is drawn dashed on the page, but only they can change it. The pills above the form switch between QA 1 and QA 2; the sidebar counts QA, not pages.
  • Pages marked extra come after the others in the list and have no reference example. Press the Extra filter to see only them; Next open page then stays among them.
  • Coordinator: unlock Admin, then open Annotate without signing in (or press Sign out). That is admin review: every page and QA is readable, and any QA can be corrected or deleted. Corrections stay under the original author.
  • Drag on the image to draw the bounding box; drag its corners to resize, drag inside it to move. It is stored as normalized_0_1000_xyxy.
  • Zoom with − and + in the toolbar, or Fit to see the whole page. When the page is larger than the window, switch to the Pan tool — or just hold Space — and drag to move around it. B and H switch between Box and Pan.
  • Press Mark complete (or ⌘/Ctrl + Enter) when the page is done. The sidebar counter tracks your completed pages.
  • Everything is saved as you type. If your connection drops or you close the tab, sign back in with the same email — your annotations return exactly as you left them, and only the image ZIP needs reloading.
